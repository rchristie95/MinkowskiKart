# Minkowski Kart gameplay capture checklist

No gameplay footage is currently available. Record genuine gameplay; do not synthesize, stage with unrelated assets or present concept art as captured play.

## Capture setup

- Use the exact build and platform being identified in the video. Windows, macOS, Linux and Android are supported working platforms; choose the one that produces the clearest genuine capture.
- Record the version/tag, commit if different, operating-system version, resolution, graphics settings, controller type and capture software in production notes.
- Capture at 1920×1080 and 60 fps if the machine can maintain it; otherwise use a stable 30 fps and disclose only the capture frame rate, not an unmeasured game-performance claim.
- Disable desktop notifications and hide account names, server addresses, file paths and tokens.
- Use only audio and assets already licensed for the game and distribution. Preserve music attribution where required.
- Keep an untouched master recording. Do not add effects that could be mistaken for game output.

## Required raw shots

Record each shot long enough to provide clean edit handles.

- [ ] Title screen with **Minkowski Kart** legible.
- [ ] Relativity settings showing the adjustable in-game speed of light.
- [ ] Starting grid, countdown and the first turn.
- [ ] Normal-speed racing for a visual baseline.
- [ ] High-beta racing with beta, gamma, `c` and proper-time telemetry readable.
- [ ] A clear retarded-position/aberration view, preferably on the Möbius track.
- [ ] The conditional Doppler-inspired colour effect, with the exact trigger recorded in the shot log.
- [ ] Time-dilation power-up activation and an affected rival within its limited radius.
- [ ] Black-hole projectile homing and its lensing effect.
- [ ] Both wormhole endpoints, entry, teleportation, exit and lensing.
- [ ] A short keyboard-control shot and a gamepad-control shot, if input display is available.
- [ ] Local split-screen play, only after both players complete a race segment successfully.
- [ ] LAN play, only after two machines or clients complete a race segment successfully. Do not imply public matchmaking.
- [ ] Finish line and results screen.

## Editorial checks

- [ ] Every effect shown came from the named build.
- [ ] No frame is labelled “gameplay” if it is concept art, debug composition or a mock-up.
- [ ] The status is **experimental**, never stable or alpha.
- [ ] Platform logos are limited to the supported Windows, macOS, Linux and Android builds and match the platform actually shown or discussed. Do not add an iOS player-support logo.
- [ ] Captions do not claim full special-relativistic dynamics or a GR simulation.
- [ ] Wormholes are described as linked teleporters with lensing, not true portal views.
- [ ] The video does not imply a public multiplayer server.
- [ ] Music, fonts, logos and gameplay assets have traceable permission.
- [ ] End card and description use <https://rchristie95.github.io/MinkowskiKart/> as the canonical URL.
