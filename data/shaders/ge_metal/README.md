The kernel binds the control-point buffer at GE_MTL_BUF_OBJECT(1), the tess-factor output at GE_MTL_BUF_SKINNING(2), and a patch-count push struct at GE_MTL_BUF_PUSH_CONSTANT(15) — the driver must adopt this binding layout (it differs from the classic per-instance ObjectData binding).
- Bindless material-id fallback (BIND_MESH_TEXTURES_AT_ONCE / gl_DrawIDARB) is mapped to [[base_instance]] in the control-point vertex stage. This only matches gl_DrawIDARB for single-draw or when base_instance is used to encode draw id; for true multi-draw-indirect it needs Metal's per-draw draw-id plumbing. Guarded exactly like the GLSL #ifdef, so it is inert in the default build. Same caveat as noted in spm.metal.
- GL->Metal depth remap: both the post-tess vertex fn and the mesh sketch apply clip.z = (clip.z + clip.w)*0.5 to match the rest of the native 3D path. Correct only if the projection matrix is NOT already baking the [0,1] remap (consistent with spm.metal); verify on-GPU that depth isn't double-remapped.
- The object+mesh-shader variant is an explicitly-labeled structural SKETCH (fixed low-res NxN lattice, one mesh threadgroup per patch, seg capped at 7). It is not fractional-odd-consistent with the classic tessellator, so shared patch edges could crack and it needs per-tile fan-out for large tess levels before production use. It is gated behind GE_TESS_MESH_SHADER and never enters the default build.
